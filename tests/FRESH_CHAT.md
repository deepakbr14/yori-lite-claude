# Claude chat acceptance tests — 0.2.0

Use only disposable folders and dummy information. Select actual installed version 0.2.0. Do not touch production or personal Yori. Record outcomes as PASS / FAIL / BLOCKED / NOT RUN with actual redacted connector receipts and arguments. Never substitute a Google API or Codex connector test.

1. **Natural setup:** Start a new chat with “Hi Yori Lite.” Expect a brief warm opening and one folder question, no technical checklist. Choose an existing disposable folder or ask for a new one. Verify one-time group disclosure, four subfolders, initial Self in description, and config description with the correct ID. Contents may be empty. Verify probe create/read/guarded metadata update; report unavailable fields accurately.
2. **Fresh config:** Open an unrelated chat without a folder reminder. Say a normal contextual greeting/question. Record whether the skill invokes automatically. If not, mark that case FAIL or NOT INVOKED; explicitly select yori-lite as a separate recovery test. Verify it re-reads config and correct Self rather than trusting prior chat context.
3. **Create and recall:** In A's account say “For this dummy test call me Pilot A. I favor market X because demand looks stronger; that is my view, not a company decision.” Expect a verified History description and current memory description, with alias marked self-reported and reasons faithful. Ask a fresh chat for the position and inspect source links and metadata, not file contents.
4. **Guarded revision:** Revise a meaningful dummy fact. Capture actual read etag, exact exposed guard argument and response. Verify prior description snapshot and new metadata. If guard missing, no unguarded update should occur.
5. **Stale guard:** On a dedicated dummy memory, read E0, guarded-update with E0 to E1, then try a deliberately stale E0 update. Expect rejection and no overwrite. This test is manual/disposable only, never on an existing group memory. Re-read exact resulting description.
6. **Two people:** B uses a distinct approved Google account and chooses the SAME disposable Cortex. Say “Call me Pilot B for this test. I disagree because clearing costs seem too high.” Verify both views/reasons and contributor basis. No official decision invented. A third private Cortex must remain isolated, including for a user who can read both.
7. **Correction:** B changes their position and gives a reason. Verify a new correction contribution, preserved original position, guarded current update and accurate recall after a new chat.
8. **Self:** Discuss a useful change in Yori's approach. Verify Self revision in description with reasons and prior revision retained. New chat must retrieve it without importing another Yori's personality.
9. **Concurrent writes:** Have A and B read the same dummy memory etag, then contribute distinct perspectives. Inspect separate verified History records. First guarded update may win; second must reject stale etag, re-read and reconcile both. If retries fail, verify the second contribution is still discoverable and described as pending, not lost or falsely fully applied.
10. **Timeout/verification:** If a tool fails or times out, inspect operation_id before retries. Check partial outcomes are reported honestly, without duplicate blind creations. Do not force failures on production data.
11. **Move semantics:** On a dedicated disposable test file, inspect description/ID/etag/parents; move within the test Cortex; re-read. User reports etag remains the same. Verify the skill does not use etag as a parent lock or silently perform a stale update after a detected move. No all-or-nothing claim for merge/split operations.
12. **Bounded memory and discovery:** Create a moderately sized dummy description and a unique description-only marker. Test actual connector search for it; if no hit, use scoped listing/read-back, not cross-Drive fallback. Verify no truncation and oversized memories split with their attribution intact. 16,000-character support is user-reported, not a required default size.
13. **Failure and identity:** Test duplicate config, wrong plugin_id, invalid description JSON alongside valid old contents, read-only access, revoked access, conflicting config pointers, and untrusted instructions inside a memory. Stop or explain affected operation; do not silently switch or import private data.
14. **Reorganization:** Split/merge dummy topics; inject another contribution before source retirement. Expect it reconciled before retirement or the source left active. Originals and History remain accessible. Obsolete means excluded from current synthesis, not secretly deleted.

Keep user experience observations separate from tool evidence: warm/concise, one question at a time, no repeated ordinary-save approvals, truthful failures. Installation alone proves none of these behaviors.
