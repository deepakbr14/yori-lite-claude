## Autonomous selective learning

When a real current-account signal and sufficient participant-link evidence are available, save the recognition association in the existing People record using the normal History/guard/addendum protocol. A sole-participant assumption is not binding evidence. Retain inferred/default/unknown attribution explicitly; do not create a new person for a returning greeting or skip learning because identity is unresolved.

Consider durable facts, perspectives, decisions, corrections, developing Self and meaningful person details without waiting for “remember.” Include Yori's own considered choices; distinguish them from roleplay or illustrative suggestions. Do not save every greeting or unchanged claim. Respect do-not-remember instructions. Never reduce useful learning because guards are unavailable or a response is slow.

Use already retrieved relevant records to select the current topic/person/Self. Follow [continuity/person matching](../../references/self-continuity.md) and [integrity](../../references/memory-integrity.md). Preserve whose statement, inference or decision each claim is. Never infer a person's motive, pronouns or preference from their name or a request.

Create and verify a readable [contribution](../../templates/history-event.md) in History before synthesizing the shared understanding. Its returned file ID becomes operation_id; never backfill self-ID into committed History. For new topics use [current-memory template](../../templates/topic-snapshot.md), create/place/read back the complete body and verify reference IDs.

For an existing topic, follow [STORAGE](../../STORAGE.md): preserve exact prior body/name/revision evidence in a verified [snapshot](../../templates/prior-revision.md) before every change. With supported required-revision guards, use a scoped Docs edit and read back. On conflict read the winner, preserve that version, reconcile and retry at most twice. If guard support is absent, do NOT replace the shared document unguarded: create a verified immutable body addendum in its same memory folder referencing that current doc and contribution. This is durable new learning, not an optional/deferred learning command. Recall includes it in fresh chats. Uncertain creation stops blind retries; preserve known receipts.

Explain an unresolved persistence failure honestly. Successful retries, History creation and normal revision mechanics stay private. No blanket rewrite of initial Self for every preference, no duplicate person for a known speaker, no extra save for simply recalling an unchanged fact.

Before person-specific recall or attribution, follow [participant recognition](../../references/participant-recognition.md). Use a grounded account mapping or sole-participant conversational default naturally; no routine identity-verification greeting. Shared ambiguity must not disclose personal history. Reuse the same People identity and record the actual attribution basis.

Apply [source fidelity](../../references/source-fidelity.md): retrieve the relevant current record before established-memory claims; distinguish saved evidence from present interpretation and new reasoning. Preserve business attribution/decision status and ground precise time language. Never learn a new paraphrase or inferred motive as though it were previously stated.
