# Sheets graph: short runtime (schema 1)

Only for `sheets-graph-v1`. Preserve the fixed plugin UUID, config_plugins bootstrap, selected folder/workbook, headers, permissions and existing data. Never select a workbook by an ambiguous name or switch a Docs installation. New setup uses Drive + Sheets, with optional account email; schema/templates are needed only during setup. Verify exact native workbook ID, folder scope, five tabs and headers once; reuse verified context within the turn. Disposable tests never change the real config pointer. Docs keeps its existing protocol.

## Choose capabilities once

Inspect the actual Claude tools, not Codex tool names or Google API assumptions. Required: genuine append, complete bounded reads/search, verification, and trusted host/provider ID generation. Atomic fast mode additionally requires one multi-tab atomic append and grouped reads. Establish these from the exposed contract and disposable test; an unclear atomicity claim needs an invalid-final-request test. Do not probe on every fact or production data. A batch name alone is insufficient. Missing optimization means use the [staged fallback](graph-recovery.md), not disable learning. No direct HTTP/auth workaround, custom server or new permissions.

## Ordinary save: five steps

1. **Reuse context.** Resolve the relevant current node and all committed heads; use the known participant/source and supported relationships. A missing search result is not proof of absence. Do not repeat setup, scan unrelated graph areas, or rewrite a whole profile. A small preference is one topic node linked to its existing participant where supported; it is not another person.
2. **Prepare once.** Keep the statement/reason in one small Node version; immutable prior versions remain untouched. History records the contribution and points to that exact revision instead of copying its content. Include genuine change reasons and all observed predecessor revision IDs. Review supported Edges, with explicit author, attribution and evidence; omit unsupported edges, never useful edges merely for speed. Use the packaged helper below when host execution is available—do not generate a Bash/Python program or hand-compute UUIDs/hashes. Reuse the saved plan on retries.
3. **Append once.** On the proven atomic path, submit the prepared requests through the actual connector, mapped to its real argument names. Nodes, Edges, contribution and final commit are in the SAME batch. One append request per tab; History contribution and commit share its rows. Only literal userEnteredValue cells: no formatting, comments, formulas, response-grid echoes, Directory or guessed next-row writes. Use `{}` for interior empty cells, omit trailing empty cells; normalize absent cells back to empty strings for verification. If a real connector exposes a compact row-array atomic append, use it with the same column values and semantics. Do not invent that interface or replace append with unsafe range updates.
4. **Verify once.** One grouped read checks every expected immutable ID, exact full payload, commit manifest and references. Prefer actual receipts; bounded tail windows from recent reads are hints, clipped to real grid bounds. Missing IDs require scoped lookup, never a false pass or blind reappend. Compare this operation only, not unrelated concurrent additions. Do not reread again after a complete successful verification or write Directory. Record verified row hints in turn context only.
5. **Continue naturally.** A verified save needs no internal narration. On uncertainty keep original operation IDs/payloads and use [recovery](graph-recovery.md); never claim persistence or invent a new operation to retry. Preserve unresolved branches and report genuine failures briefly. The two-Sheets-call target excludes needed discovery, preparation, pre-reads and exceptional recovery; count them honestly.

## Fixed helper, compact input

`scripts/save_memory.py --json '<intent JSON>' --plan '<unique local plan path>'` is a packaged standard-library helper, not a new backend. Invoke it with the host execution tool using proper argument quoting; do not create an inline script. It prints only compact connector arguments and stores exact recovery IDs locally. It does not call Sheets, authenticate, inspect current heads, or prove a source/relationship. The host still needs to send its output through the real connector. Re-running with the same path and identical intent reuses the plan; changed intent is rejected.

Intent fields: verified `spreadsheet_id`, numeric `sheet_ids` for Nodes/Edges/History, `kind`, `title`, `content`, `contributor`, `attribution`, `source`; optional `subject`, actual `event_time`, and `reason`. A correction also needs existing `node_id`, all current `bases`, next display `version`, original `created_at`, and `reason`. Optional `edge` has `to`, `relation`, `evidence`, `contributor`, `attribution`; endpoint must be verified. This convenience path creates one new edge, so reuse an existing unchanged edge instead; edge revisions/multi-node operations use packaged batch_memory.py with verified rows. No profile duplication or prose re-explaining the transaction.

Do not read helper source or all legacy references each turn. No host execution? Use an actually exposed trusted ID/preparation facility if available; do not claim this helper supplies it. Existing schema-1 manifests require a hash OR exact payload for each member. The helper computes each required SHA-256 once. No optional aggregate hashes or extra hash tool calls; hashes are smaller than duplicated payloads. Removing these required checks without a new compatible integrity design is not a performance shortcut. Never fabricate hashes or random-looking IDs. If safe preparation is unavailable, state the specific blocked write capability; recall remains usable.

## Integrity and recall invariants

Nodes and Edges remain first-class immutable full versions with stable entity IDs and unique revision/operation IDs. History contributions and commit markers remain append-only. Attribution distinguishes explicit statements, external evidence, inference, independent decisions, mixed and unknown. Keep speaker uncertainty, original reasons, source context and event time; do not infer gender, motive, agreement or commitments. Blank optional fields are unknown, never invented. Original Self development and selective automatic learning remain active.

A commit is valid only with all manifest members present, matching, unambiguous and in the same operation. Identical-ID identical-payload duplicates count once; mismatches are corruption. Existing hashes/exact-payload manifests remain readable. Two revisions of the same base remain competing heads; timestamps/version numbers never choose a winner. Atomic append is not compare-and-swap, snapshot isolation or exactly-once delivery. Reject cyclic, missing or cross-entity predecessor links. Human editors can still corrupt cells; no immutable ACL is claimed.

Current Self/People/Knowledge nodes precede History-only hits. Resolve committed heads and explicit amendments; follow supported edges one hop by default, then two when useful. Incomplete scan coverage stays explicit; high-degree relationships require pagination. Row numbers/Directory are hints checked against IDs and commits, never identity or a write location. A legacy profile-to-topic amendment retains the original profile revision and explicit source link; recall checks it rather than repeating stale profile text. No automatic bulk splitting, merging or migration. Preserve full content; a cell/connector limit blocks that record rather than truncating it. See recovery only when conflict, schema, traversal, legacy-source preservation or reorganization needs more detail.
